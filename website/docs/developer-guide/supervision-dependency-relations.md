# Source-linked supervision dependency relations

This optional host owner keeps **advisory semantic relations**, not truth,
permission, finality, instruction replacement, or whole-request coverage.
It runs inside the existing runtime and uses its settlement seam; it has no
separate database, background patrol, inference retry, or model-visible tool.

## Ordinary producers

- An authenticated accepted request supplies exact enumerated clauses. A later
  authenticated user continuation advances the instruction epoch before any
  dependent scheduling. Same-authority relations use only clauses sharing a
  literal reference and already known dependency edges. Original clauses remain.
- A committed main-agent write to a designated artifact may contain the existing
  `hermes-work-map-v1` block. Its public grammar is unchanged. The parser now pins
  claim spans to their exact artifact version as well as requirement spans.
  A successful read or child/external file cannot authorize a work map.
- A native complete `read_file` result can supply source bytes. The parser removes
  only literal line gutters and requires byte length and SHA-256 equality with
  the native read's descriptor snapshot. Partial, redacted, extracted-document,
  remote, non-exact, or oversized output cannot become a complete source.
  A changed native descriptor digest invalidates an older source even if the
  newly returned page is partial.
- A changed final containing a unique exact work-map claim can be checked against
  literal source refs in that claim, resolved to retained bounded artifact/read
  bytes. The complete bounded claim artifact supplies qualifier context, and the
  complete source is preserved. Work-map requirement substrings that cut an
  enumerated clause/qualifier do not qualify. No topical matching or singleton
  requirement inference is used.

Bounds are 64 dependency edges, 64 current request bindings, 32 instruction
relation receipts, up to eight final opportunities, four sources per claim,
2,400 characters per complete source/claim context, and the existing transport
byte/question caps. Exhaustion abstains; global coverage remains unknown.

## Negotiation and effects

`dependency_relations_version = supervision.dependencies.v1` and an exact
`dependency_relations` mapping advertise three closed optional codecs:

| Feature action | Native action |
|---|---|
| `support_edge` | `update_dependencies` |
| `affected_dependency_invalidation` | `update_dependencies` |
| `targeted_gap` | `continue` |

Negotiation is not a grant. Registration separately requests these actions and
intersects them with profile policy. All plural relation records are validated
against the exact native opportunity, claim, source ref, requirement and current
work-map/todo/source versions at both submission and consumption. Unknown keys,
scalar stand-ins, truth/finality flags, foreign refs and duplicate rows reject.
The previous four optional view/receipt codecs are preserved.

Support can avoid rechecking an identical supported relation in a later eligible
final; it never proves source truth, freshness or evidence sufficiency. A
contradiction keeps both exact texts and suspends confident optional reuse for
the whole affected claim, including its otherwise supporting edges. Source
version invalidation is immediate and deterministic, even with no plugin.
`evidence_revoked` observations report those known changed dependencies without
inventing comparable entities, dates or units.

Instruction relations only mark named existing dependencies for reevaluation.
The original instruction epoch and plan-binding fences already prevent stale
reuse immediately. Unrelated source relations are not erased. System/developer
instructions are neither transmitted nor rewritten by this user-clause path.

A high-confidence named gap may use the existing final continuation. F20
`coverage_windows` retains priority and its full original subset scheduling.
All final windows share one absolute deadline and one existing continuation
budget. A support result is consumed before expiry without closing still-pending
coverage windows. If another gap used the continuation, consumed relation state
is recorded as a relation effect, not a fictitious second continuation or no-op.
Rejected final prose is not emitted as interim commentary by this owner. Already
streamed text cannot be recalled.

## Bounded pre-action re-anchoring

An actual committed change from an old todo target to a different target binds
the proposed action to the **current** step's accepted requirements. Proposed
arguments, current todo/version and map pin are rechecked at the effect boundary.
The advisory is once per exact changed plan link, not once per retried tool call;
an unchanged retry remains available to the main agent. Permission and mandatory
execution gates remain owned by the ordinary dispatcher.

Work-map v1 contains no prerequisite or cleanup declaration. These facts are
explicitly **null/unknown**, never fabricated negatives. The paired F09 policy
allows an explicitly unknown relationship to be classified, bypasses known
prerequisite/cleanup work, and abstains for necessary-prerequisite,
required-cleanup or insufficient judgments. This is a scoped policy correction:
missing fields still reject; no new work-map keys or model permission declarations
were added. `current_authorization` means current accepted requirement provenance,
not authorization to execute the proposed tool.

## Remaining contract limits (not complete F22 coverage)

The available work-map grammar and native file receipts do **not** supply an
owner-qualified entity/time/scope/unit comparison contract, nor a receipt that a
particular delivered claim was consequential. A shared filename, newer source,
model-authored qualifier map, or F17 judgment cannot supply those facts. Therefore
this owner does not advertise `contest_dependent_claim` / `focused_correction`
as implemented F22 codecs. Deterministic source invalidation and F17 contradiction
suspension are implemented; a general F22 pair-classification and delivered
material-correction vertical remains unresolved. No separate model turn is
created to announce that uncertainty. Additional retrieval owners must provide
authentic exact source windows through their own contracts; this implementation
qualifies native file results and committed designated artifacts only.

### Exact missing producers and required design decision

- `supervision_context.parse_work_map` only produces exact requirement/claim
  spans and todo/target links. `record_file_owner_read` / `record_file_owner_commit`
  produce exact bytes and version pins, not typed propositions. Neither can
  produce F22's `comparability.entity/time/scope/units = True` from those facts.
  A source-qualified pair producer must supply **both** exact proposition refs,
  full qualifiers, canonical entity/predicate identity, observation/event-time
  interval, scope/conditions and quantity/unit semantics (including an explicit
  non-quantity case), plus current dependent IDs/versions. An unknown coordinate
  must stay unknown, not become a matching default.
- `prepare_final` sees a candidate, not a surface delivery acknowledgment. There
  is no ordinary producer here for `delivered_consequential`: it needs an exact
  claim-to-delivered-message/span receipt and an owner-defined consequence policy,
  with profile/lineage/work/generation and current correction/incident identity.
  A successful file write, transcript presence or F17 support cannot supply this.
- `SupervisionFacade.evaluate_relation` / `OwnerRequestV1.facts` is a generic
  proposal seam, not either missing producer. The standalone adapter now reports
  `contest_dependent_claim` and `focused_correction` as unsupported owner effects;
  it no longer disguises them as generic relation/continuation codecs.

The minimal design decision is to designate an **existing structured evidence
owner and its ordinary result schema** as the authority for those comparison
coordinates, and designate the **existing delivery owner** for claim-linked
acknowledgment and consequence policy. Agree an owner-local, versioned contract
and actual caller at those two boundaries before implementing pair/correction
consumption. If no such structured producer exists, a new source contract needs
explicit design approval. Extending work-map-v1 or asking a model to fill in
comparability would not resolve the missing authority.

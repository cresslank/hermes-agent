# Native literal correction notices

This optional local implementation joins a historical, source-backed whole answer
to later evidence. It is not a truth adjudicator, background research agent or
permission to replay a send. Unsupported source/output shapes preserve baseline
completion delivery. Live deployment and model quality are separate qualification.

## Native facts and separate decisions

An original must already have an accepted requirement link, an adopted complete
literal-source rendering, a post-hook whole-final match and a canonical native
`original_emitted` record. Those facts support
`native_whole_answer_dependency.v1`. They do not infer that every sentence was
mandatory: `required_answer_intent` remains `unknown` unless another authentic
owner establishes it.

The native source provider enrolls bounded custody only from that actual original
owner. Custody contains provenance, not continuing publication or inference
permission. Replacing/closing the source registration withdraws it, including a
re-registration with the same provider and unchanged configuration. Restart or
SessionDB replacement restores historical rows, not old origin or send authority.

Late worker hydration is associated with the native child/control IDs and the
canonical completion admission, not references or flags asserted in worker prose.
A source append/batch/delete can also write compact outbox metadata in its own
existing SQLite transaction. Only committed changes enter the existing routed
completion queue. A failed deletion does not mark custody unavailable. Optional
metadata/callback failures do not turn an already-completed source write into a
retry request. Source absence/deletion is unavailability, not factual retraction.

The main owner reviews one linked pair per safe point. It preserves the original
work identity while binding the review to the current session, generation, source
registration and canonical predecessor records. Different entity, predicate,
time, scope or units abstain. Exact numeric incompatibility is deterministic.
Other relations require the separate bounded semantic grant below. No corpus
sweep or automatic broad re-research runs.

The semantic question can establish an incompatible relation, not a winner. A
relation-only F22 proposal authorizes only the native canonical contest. Notice
selection and source presentation remain separate main-owned effects. Missing,
expired, revoked or unsupported judgment produces no accepted contest. Both exact
references and the unknown truth winner are retained. Canonical contest records
also restore optional-support suspension when the dependency owner reloads; they
do not rewrite the original historical adoption or original output.

## Configuration contract, not activation instructions

The native source policy is off unless explicitly configured under the registered
LCM source owner:

```yaml
supervision:
  plugins:
    hermes-lcm:
      literal_sources:
        correction_review:
          version: supervision.literal-correction.v1
          consumer: native:main-correction
          enabled: true
        correction_semantic:
          version: supervision.literal-correction.v1
          recipients: [example-supervisor]
```

Existing source registration, accepted-final and original-output policies remain
necessary. The additional semantic recipient must have `observe`,
`contest_dependent_claim`, and the local history/project/task classes. Its
per-field egress policy must separately authorize `a` and `b` with source purpose
`supervision.literal-correction.v1`, as well as every other emitted fact, including
`relation_only`. The plugin applies its independent class/private-source policy.
A local correction/read grant never implies remote disclosure permission.

Source reads occur before host/recipient/write fences. Recipient/source/currentness
checks repeat at actual remote dispatch and canonical contest commit under the
original shared judgment deadline. A classification result is not a durable
contest receipt; only successful canonical persistence settles application.

## Once-only output and limits

Supported notices use the original proven audience and transport through native
CLI, Telegram forum-topic and TUI stdio owners. A separate correction scope does
not replace the current answer's original-output scope. Before sending, the owner
rereads the exact source pair and persists a selected intent. Failed/uncertain
persistence does not send. A send without a durable emitted receipt remains
unknown and is never automatically repeated. Actual emitted bytes, target,
transport generation, frame/message identity and origin codec are checked again
at acknowledgement. This does not prove client rendering or human reading.

All state is bounded: at most 64 enrolled originals/candidate source events and
four admitted incidents in the current runtime. Source batches above eight and
matches affecting more than four originals abstain rather than truncate. Capacity
loss is unavailable, not a false success. Persisted unresolved incidents and
outbox rows are facts, not a restarted process's permissions or replay queue.

The source domain remains complete native literal records; the original-output
codec restrictions documented in `supervision-literal-sources.md` still apply.
Required/unknown ordinary completion delivery and API no-wake behavior must remain
independent. The focused ordinary child-construction and actual Gateway/TUI
continuation qualification is a separate integration lane until its tests land.
Neither this document nor the local scalar/sink tests constitute full F22 closure.
